SAIDA
Responda SOMENTE com um objeto JSON valido, sem markdown, sem cercas de
codigo e sem texto antes ou depois. Qualquer observacao vai em
reviewer.notes.

Regras dos achados:
1. Cada achado trata de UMA unica afirmacao problematica (um erro real ou
   uma suspeita concreta). PROIBIDO emitir verificacoes que deram certo
   ("Sem erro", "Confere", "Consistente", "Conta correta", "Verificacao OK").
   O array "findings" deve conter APENAS problemas encontrados.
2. line_start e line_end cobrem so as linhas em que o problema aparece, com
   no maximo {{MAX_LINHAS}} linhas (line_end - line_start + 1), sempre com
   line_start <= line_end e inteiros JSON sem zeros a esquerda (ex.: 889,
   nunca 0889). Se o problema envolve trechos distantes, emita achados
   separados. Nao use intervalos largos para "cobrir" o assunto.
3. No maximo {{MAX_ACHADOS}} achados. Priorize os de maior confianca.
4. status, exatamente um de:
   - CONFIRMADO: erro inequivoco (numerico, estatistico, de unidade ou
     contradicao interna direta) em que voce refez a conta ou mostrou a
     contradicao citando as linhas, e isso esta em "evidence". Nao use
     CONFIRMADO para typos triviais, estilo, limitacoes metodologicas ou
     verificacoes sem erro.
   - TRIAGEM: suspeita plausivel, sem demonstracao completa.
   - NAO_VERIFICADO: nao da para verificar so com o texto (por exemplo,
     depende de referencia, dado ou figura que nao esta no texto).
5. claimed_value e o numero que o manuscrito declara. recomputed_value e o
   numero CORRETO que voce obteve ao refazer a conta. Ambos devem ser
   NUMEROS JSON (ponto decimal, ex.: 16.5), nunca texto, nunca com unidade
   e nunca "16,5". Se voce NAO recalculou um valor diferente do declarado,
   use null em recomputed_value (nunca copie claimed_value para
   recomputed_value). Use null em ambos se o achado nao for numerico. A
   unidade vai em "evidence".
6. excerpt: no maximo 15 palavras do manuscrito, ou "".
7. evidence: no maximo 400 caracteres, com a conta ou a contradicao (cite
   os numeros das linhas envolvidas).
8. category: texto livre em snake_case, sem acentos.
9. Confira cada numero de linha antes de emitir. Nao invente linhas.
10. Se nao encontrar problemas reais, devolva "findings": []. Nao force
    achados e nao registre checagens aprovadas.

Formato:
{
  "document": "{{DOC_ID}}",
  "document_sha256": "{{DOC_SHA256}}",
  "reviewer": {
    "reviewer_model": "{{MODELO}}",
    "session_id": "{{SESSAO}}",
    "saw_gabarito": false,
    "saw_pareceres": false,
    "saw_auditor_results": false,
    "notes": "ferramentas ativas; reconheceu o artigo (sim/nao); numero da ultima linha lida; limitacoes"
  },
  "findings": [
    {"line_start": 0, "line_end": 0, "category": "...",
     "status": "TRIAGEM", "excerpt": "", "claimed_value": null,
     "recomputed_value": null, "evidence": ""}
  ]
}
Use true em um saw_* somente se for verdade, e explique em notes.
